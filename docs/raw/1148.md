¶ 前言

本文是一篇实战教程，旨在引导你通过自定义 MCP（Model Context Protocol）工具，结合语音指令控制硬件设备。我们将以 Arcs-mini 开发板为例，展示如何通过语音触发串口通信，最终在扩展 GPIO 接口输出串口信息。

无论你是物联网开发者、嵌入式爱好者，还是希望将语音交互能力接入硬件项目的创客，本教程都将带你一步步实现一个完整的 “语音—串口—GPIO” 软硬件联动示例。

你将学习到如何配置 MCP 工具、编写串口控制逻辑，并实现语音到硬件的无缝控制。

¶ 1. 服务层与构建接入

串口服务位于：

apps/arcs-mini/services/service_uart1.c

apps/arcs-mini/services/service_uart1.h

并在 apps/arcs-mini/services/CMakeLists.txt 中加入 service_uart1.c。虽然文件名沿用 uart1，但 Mini3 编译时实际使用 UART2。

¶ 2. 按板型选择 UART 和引脚

代码通过 CONFIG_BOARD_ARCS_MINI3 选择设备实例和 pinmux：

#ifdef CONFIG_BOARD_ARCS_MINI3
#define UART_DEVICE      "uart2"
#define UART_TX_PAD      CSK_IOMUX_PAD_B
#define UART_TX_PIN      6U
#define UART_RX_PAD      CSK_IOMUX_PAD_B
#define UART_RX_PIN      7U
#define UART_FUNC        CSK_IOMUX_FUNC_ALTER4
#define UART_PINMUX_FN   lisa_uart2_pinmux
#else
#define UART_DEVICE      "uart1"
#define UART_TX_PAD      CSK_IOMUX_PAD_A
#define UART_TX_PIN      4U
#define UART_RX_PAD      CSK_IOMUX_PAD_A
#define UART_RX_PIN      5U
#define UART_FUNC        CSK_IOMUX_FUNC_ALTER3
#define UART_PINMUX_FN   lisa_uart1_pinmux
#endif

初始化时通过 lisa_device_get(UART_DEVICE) 获取对应 LISA UART 设备，再配置 2 个、每个 256 字节的循环接收缓冲区并开启 RX。

¶ 3. 串口回显与异常恢复

接收任务阻塞调用 lisa_uart_read_sync()；收到数据后调用 service_uart1_send() 原样回发。如果驱动报告 LISA_DEVICE_ERR_OVERFLOW，必须按驱动约定重启接收，否则会持续返回溢出错误：

int r = lisa_uart_read_sync(uart_dev, buf, sizeof(buf));
if (r > 0) {
    service_uart1_send(buf, (uint32_t)r);
} else if (r == LISA_DEVICE_ERR_OVERFLOW) {
    lisa_uart_rx_disable(uart_dev);
    lisa_uart_rx_enable(uart_dev);
}

¶ 4. 注册 MCP 工具

MCP 工具位于 apps/arcs-mini/mcp-tools/mcp_tool_uart1.c，在对应 CMakeLists.txt 中参与编译。工具只接收一个必填字符串参数 content，调用 service_uart1_send() 发送文本：

MCP_TOOL_DEFINE(uart1_send, mcp_tool_uart1_list, mcp_tool_uart1_call);

Mini2 的工具描述显示 UART1 PA04/PA05，Mini3 的描述显示 UART2 PB06/PB07；工具注册名保持 uart1_send，避免破坏已有云端编排。

¶ 5. 编译验证

.\build.ps1 -S .\apps\arcs-mini -B build-uart-mini -DBOARD=arcs_mini
.\build.ps1 -S .\apps\arcs-mini -B build-uart-mini3 -DBOARD=arcs_mini3

两个板型均应成功生成 arcs-mini.bin、LPK 和 combined HEX。实际接线时，串口模块 TX 要接开发板 RX，串口模块 RX 要接开发板 TX，并共地。
