¶ 1. 按键编号和功能边界

GPIO 按键驱动使用注册数组下标作为内部按键编号。本例一次注册主功能键和四个方向键，编号固定如下：

方向/用途

 | 主功能键
 | 板载功能键

 | 1
 | up
 | 上

 | 2
 | left
 | 左

 | 3
 | right
 | 右
 | SW3

 | 4
 | down
 | 下

编号顺序为“上、左、右、下”，与模组从 SW1 到 SW4 的实际布局一致。内部编号和对外字符串 ID 必须同步修改，不能只改 MCP 能力声明，否则云端看到的方向会与真实按键事件不一致。

当 CONFIG_MINIAPP_BUTTON=y 时，四个方向键的行为边界是：

小应用运行时，Btn1～Btn4 转换为 up、left、right、down，交给 Lua 的 on_button_click(button_id)。

小应用未运行时，方向键不触发旧的相机预览或配置二维码快捷行为。

Btn0 仍是主功能键，继续承担设备原有功能；小应用运行时也可作为 function 传给 Lua。

方向键事件仍会被电源策略视为一次用户活动，但不会再跳转相机页或二维码页。

¶ 2. GPIO 注册和电平读取

四位十字按键模组按下时将对应 GPIO 接地。固件把方向键配置为输入上拉，因此：

按键状态
GPIO 电平
驱动判断

 | 松开
 | 高电平
 | 未按下

 | 按下
 | 低电平
 | 已按下

service_button_init() 先把方向键引脚切换为普通 GPIO，再构造包含五个按键的注册表。Arcs-Mini2 的五个按键同时使用 GPIOA 和 GPIOB；Arcs-Mini3 还会同时使用 PA 和 PB 引脚，因此 lisa_btn_gpio_item_t 增加了按键级 gpio_dev_name：

Mini3 的 GPIO 复用功能号并不统一：PA00/PA01 必须使用功能 1，PB06/PB07 使用默认功能 0。按键服务为每个方向分别保存并应用 iomux_func，不能把四个引脚都配置为 CSK_IOMUX_FUNC_DEFAULT，否则 Btn1/Btn2 无法检测到电平变化。

Mini3 的 PA00/PA01 原本连接 4G 模块的 EN/RST。方向键固件会将它们重新配置为输入，因此该固件不能同时使用这两个 4G 控制信号；按下按键也会拉低相应硬件连线。

typedef struct {
    const char *gpio_dev_name;
    uint8_t pin_num;
    uint8_t iomux_func;
    uint8_t active_level;
    bool pull_enable;
    bool pull_up;
} lisa_btn_gpio_item_t;

lisa_btn_gpio_init() 会为每个按键保存对应的 GPIO 设备，并在扫描时根据 btn_id 选择正确的 GPIOA 或 GPIOB 实例。未填写按键级设备名时，仍回退到配置级 gpio_dev_name，保留旧调用方式的兼容性。

¶ 3. 单击事件转换

方向键只向小应用暴露 click，不暴露按下、释放、长按或连击。一次短按的典型日志如下：

[GPIO Btn2] event=0
[GPIO Btn2] event=10
[Button 2] action=1

其中：

event=0 表示按下。

event=10 表示短按释放。

按键服务立即把短按释放转换为一次 click，发布为 action=1。

FlexibleButton 稍后还会生成原始 event=1 点击汇总事件，按键服务会将它丢弃，避免一次按键向小应用重复上报两次。

因此方向键适合贪吃蛇、2048、迷宫、菜单等“单击一步”的小应用。若未来需要按住连续移动，必须先扩展端侧事件模型和 Lua API，再在能力声明中增加对应事件，不能只修改 events 字段。

¶ 4. 方向键事件链

方向键从物理输入到 Lua 回调依次经过：

GPIO 电平
  -> lisa_btn / FlexibleButton 消抖与识别
  -> service_button 转换为一次 CLICK
  -> VOICE_MSG_BUTTON_CHANGE
  -> app_button 将数字编号转换为方向 ID
  -> miniapp_button_click() 写入小应用事件队列
  -> Lua on_button_click(button_id)

app_button_miniapp_id() 是内部数字编号到小应用字符串 ID 的边界：

0 -> function
1 -> up
2 -> left
3 -> right
4 -> down

Lua 小应用统一通过以下回调处理方向键：

function on_button_click(button_id)
  if button_id == "up" then
    -- 向上移动
  elseif button_id == "left" then
    -- 向左移动
  elseif button_id == "right" then
    -- 向右移动
  elseif button_id == "down" then
    -- 向下移动
  elseif button_id == "function" then
    -- 可选：暂停、确认等功能
  end
end

miniapp_button_click() 只接受 function、up、left、right、down，非法 ID 或没有小应用运行时返回错误，不会把未知按键送入 Lua。

¶ 5. 隔离旧 UI 快捷键

原 UI 代码曾把 Btn1 用作相机快捷键、Btn2 用作信息页快捷键。方向键接入后，Btn2 已经代表左键，如果保留旧处理会出现“按左键打开配置二维码”的冲突。

apps-ui/apps/llm/models/model_voice.c 在 CONFIG_MINIAPP_BUTTON=y 时会忽略所有非 Btn0 的旧 UI 快捷处理：

#ifdef CONFIG_MINIAPP_BUTTON
if (evt->button_id != 0U) {
    return;
}
#endif

该判断与“小应用当前是否正在运行”无关，所以在正常业务页面按方向键也不会打开二维码或相机页面。没有启用 CONFIG_MINIAPP_BUTTON 的其它固件仍保留原有 UI 按键行为。

¶ 6. MCP 设备能力声明

ls.built_in.get_device_capabilities 的 hardware.input.buttons 会返回主功能键和四个方向键。Arcs-Mini2 的核心结果如下：

{
  "hardware": {
    "input": {
      "buttons": [
        {"id":"function", "events":["click"]},
        {"id":"up", "label":"上", "pin":"PA4", "direction":"up", "events":["click"]},
        {"id":"left", "label":"左", "pin":"PA5", "direction":"left", "events":["click"]},
        {"id":"right", "label":"右", "pin":"PA6", "direction":"right", "events":["click"]},
        {"id":"down", "label":"下", "pin":"PA7", "direction":"down", "events":["click"]}
      ]
    }
  }
}

Arcs-Mini3 使用相同的 ID 和方向顺序，四个 pin 自动变为 PA0、PA1、PB6、PB7。云端生成小应用时应使用 id 作为回调参数，不依赖 GPIO 编号。

¶ 2. 普通业务页面

在没有运行小应用时依次按四个方向键，应满足：

不打开配置二维码。

不进入相机预览或拍照。

不触发主功能键的唤醒、配网或关机逻辑。

其中左键日志可出现：

[GPIO Btn2] event=0
[GPIO Btn2] event=10
[Button 2] action=1
button evt id=2 action=1
ignore button_id=2

不应再紧跟：

Invoking on_info_show callback

¶ 3. 小应用页面

让小聆生成一个“显示最近方向键并用方向键移动方块”的小应用，然后依次按上、左、右、下：

屏幕中的方块移动方向应与实体按键一致。

on_button_click() 应依次收到 up、left、right、down。

每次短按只响应一次，不应出现一次按键移动两格。

长按主功能键 3 秒仍可退出小应用。

¶ 4. 能力探测

调用 ls.built_in.get_device_capabilities，确认：

hardware.input.buttons 包含 function、up、left、right、down。

四个方向键仅声明 events: ["click"]。

pin 与当前构建板型一致。

若 GPIO 日志正确但小游戏没有响应，先检查云端生成的 Lua 是否实现 on_button_click(button_id)，以及是否处理全部四个方向 ID。只支持 function 的旧小应用需要让云端重新查询设备能力并重新生成。
