¶ 前言

本文是一篇实战教程，旨在引导您通过自定义 MCP（Model Context Protocol） 工具，结合语音指令控制硬件设备，实现智能环境监测。

我们将以 Arcs-mini 开发板为核心，展示如何通过语音触发 I2C 通信，驱动外接温湿度传感器，并实时返回环境数据。

无论您是物联网开发者、嵌入式爱好者，还是希望将语音交互能力融入硬件项目的创客，本教程都将带您一步步构建一个完整的“语音—I2C—传感器数据”软硬件联动系统。您将学习到如何配置 MCP 工具、编写 I2C 传感器驱动，并实现从语音指令到实时数据采集的无缝交互。

¶ 1. 服务层与构建接入

AHT10 服务位于：

apps/arcs-mini/services/service_aht10.c

apps/arcs-mini/services/service_aht10.h

服务文件在 apps/arcs-mini/services/CMakeLists.txt 中参与编译，提供以下三个接口：

int service_aht10_init(void);
int service_aht10_read_data(float *humidity, float *temperature);
int service_aht10_get_temperature_humidity(float *humidity, float *temperature);

应用启动时由 apps/arcs-mini/main.c 调用 service_aht10_init()，完成引脚复用、I2C0 初始化和 AHT10 上电等待。

¶ 2. 按板型选择 I2C0 引脚

服务通过 CONFIG_BOARD_ARCS_MINI3 选择引脚，Mini2 原有功能保持不变，Mini3 改用 PB06/PB07：

#ifdef CONFIG_BOARD_ARCS_MINI3
#define SERVICE_AHT10_I2C_PAD       CSK_IOMUX_PAD_B
#define SERVICE_AHT10_SDA_PIN       (6U)
#define SERVICE_AHT10_SCL_PIN       (7U)
#define SERVICE_AHT10_SDA_NAME      "PB06"
#define SERVICE_AHT10_SCL_NAME      "PB07"
#else
#define SERVICE_AHT10_I2C_PAD       CSK_IOMUX_PAD_A
#define SERVICE_AHT10_SDA_PIN       (5U)
#define SERVICE_AHT10_SCL_PIN       (4U)
#define SERVICE_AHT10_SDA_NAME      "PA05"
#define SERVICE_AHT10_SCL_NAME      "PA04"
#endif

#define SERVICE_AHT10_I2C_FUNC      CSK_IOMUX_FUNC_ALTER8

初始化时显式覆盖目标引脚的 pinmux，然后获取 I2C0 驱动实例：

IOMuxManager_PinConfigure(SERVICE_AHT10_I2C_PAD,
    SERVICE_AHT10_SDA_PIN, SERVICE_AHT10_I2C_FUNC);
IOMuxManager_PinConfigure(SERVICE_AHT10_I2C_PAD,
    SERVICE_AHT10_SCL_PIN, SERVICE_AHT10_I2C_FUNC);

g_i2c_dev = I2C0();
I2C_Initialize(g_i2c_dev, aht10_i2c_cb, NULL);
I2C_PowerControl(g_i2c_dev, CSK_POWER_FULL);
I2C_Control(g_i2c_dev, CSK_I2C_TRANSMIT_MODE, 0);
I2C_Control(g_i2c_dev, CSK_I2C_BUS_SPEED, CSK_I2C_BUS_SPEED_STANDARD);
I2C_Control(g_i2c_dev, CSK_I2C_BUS_CLEAR, 0);

¶ 3. AHT10 通信与数据换算

AHT10 默认 7 位地址为 0x38。服务使用异步 I2C 回调记录传输事件，并在每次读写后等待完成：

读取状态寄存器，检查校准位和忙状态。

未校准时发送初始化命令 E1 08 00。

发送测量命令 AC 33 00。

等待测量完成后读取 6 字节数据。

从返回值中提取两个 20 位原始值，并换算为湿度和温度。

uint32_t raw_humi = ((uint32_t)data[1] << 12)
    | ((uint32_t)data[2] << 4)
    | ((data[3] & 0xF0) >> 4);
*humidity = (float)raw_humi * 100.0f / 1048576.0f;

uint32_t raw_temp = ((uint32_t)(data[3] & 0x0F) << 16)
    | ((uint32_t)data[4] << 8)
    | data[5];
*temperature = (float)raw_temp * 200.0f / 1048576.0f - 50.0f;

¶ 4. 按键测试入口

apps/arcs-mini/button/app_button.c 在电源键四击事件中调用 service_aht10_get_temperature_humidity()，读取成功后通过日志打印温度和湿度。该入口适合在接入云端 MCP 前先验证传感器接线和 I2C 通信。

¶ 5. 注册 MCP 工具

MCP 工具位于 apps/arcs-mini/mcp-tools/mcp_tool_aht10.c，并在对应 CMakeLists.txt 中参与编译。该工具没有输入参数，调用时直接读取传感器：

MCP_TOOL_DEFINE(sensor_temperature_humidity,
    mcp_tool_aht10_list,
    mcp_tool_aht10_call);

工具返回文本格式为“当前环境温度为 xx.x°C，湿度为 xx.x%”。读取失败时返回 isError=true，提示检查传感器连接。工具描述会根据目标板型显示实际 I2C 引脚，但注册名保持不变，避免破坏已有云端编排。

¶ 6. 编译验证

.\build.ps1 -S .\apps\arcs-mini -B build-aht10-mini -DBOARD=arcs_mini
.\build.ps1 -S .\apps\arcs-mini -B build-aht10-mini3 -DBOARD=arcs_mini3

两个板型均应成功生成 arcs-mini.bin、LPK、OTA 和 combined HEX。实板验证时，先确认 AHT10 供电和共地，再通过电源键四击或语音指令“环境温度湿度多少”触发读取。
