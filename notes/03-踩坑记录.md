# 踩坑记录

开发和调试过程中实际遇到的问题，按环节分三类整理，便于对照排查。

> 本文档面向后续维护者。对外说明请见 README。

---

## 播放链路

| 现象 | 真正原因 |
|---|---|
| 工具返回「正在播放」但没声音 | B 站直链 769 字节 > 固件 `url[512]`，被静默截断 |
| 设备连上 `/stream` 立刻断开 | 设备不收 m4s 容器，必须转 MP3 + 支持 Range |
| 单词能播、带空格的一定失败 | WBI 签名把空格编成 `+`，B 站要 `%20`；`urlencode` 默认给 `+` |
| 重启后突然连不上服务 | 电脑 DHCP 换了 IP，固件里写死了旧地址 |

## 云端 LLM 行为

这一类最耗时——问题不在代码，而在云端 LLM 的工具选择行为不可控。

| 现象 | 真正原因 |
|---|---|
| 换工具名后她说「曲库没有」 | 云端 LLM 只认已验证过的工具名，新名字直接当不存在 |
| 工具描述写「屏幕选择」后她说「设备不支持」 | LLM 读到交互细节，判断设备不具备该能力 |
| 多个音乐工具并存时她干脆不调 | 收敛成一个入口 |
| 音乐在放但她同时说「无法播放」 | 端侧接管了点歌，但云端那轮会话没取消——要 pub `VOICE_MSG_CLOUD_SESSION_INTERRUPT` |
| 同一句话这次调下次不调 | LLM 的工具选择本身不稳定；本项目的做法是端侧直接拦 ASR，不依赖 LLM 决定 |

### 结论

不要试图用工具名 / 描述 / 删内置工具去"引导" LLM，全部不稳定。最终方案：

```
订阅 VOICE_MSG_CLOUD_IAT_UPDATE   记录识别文本
订阅 VOICE_MSG_CLOUD_IAT_END      提取「播放/来首/听」后的歌名
  → pub VOICE_MSG_CLOUD_SESSION_INTERRUPT + MCP_CHAT_EXIT（掐掉云端回复）
  → async_task 里请求 /search → pub 列表
```

注意 `VOICE_MSG_CLOUD_IAT_END` 才会触发；`VOICE_MSG_RECOGNIZED_SESSION_FINISH` 来自 rcmd_router，条件不明，实测从不触发。

## 界面与资源

| 现象 | 真正原因 |
|---|---|
| LVGL 控件设了坐标却跑位 | 父容器 `lisa_ui_llm_primary` 是 FLEX COLUMN，要加 `LV_OBJ_FLAG_IGNORE_LAYOUT` |
| `undefined reference to lv_font_chinese_18` | 那个字体在 CMakeLists 里被注释掉了，实际符号是 `lv_font_chinese_16` |
| 封面位置空白/花屏 | 颜色深度搞错，详见下方专节 |
| 封面消息发不出去 | ebus 的 `pub_async` 用 `platform_malloc` 拷贝 payload，SRAM 已用 99%，8KB 必然 ENOMEM；改传 PSRAM 指针 |
| 界面整体卡死 | 在 ebus 回调里同步做 HTTP（1~8 秒）堵死事件总线，必须移到 `async_task` 独立线程 |
| 待机表情变回官方 9 帧 | `emoji.json` 的 `default_emoji` 指向官方的 `neutral`，但分区里只有中文目录，加载失败回退到 app 内置官方表情 |
| 表情被云端刷回官方 | `user.disable_emoji_update=1` 未设置（固件启动时会自动补设） |
| 唤醒词改了不生效 | `user.disable_wakeword_update=1` 挡住了 OTA |
| 唤醒第一句是男声 | 那不是 TTS，是 `tone` 分区里的本地 `00x_greeting.mp3` |
| C 源码写中文标点编译失败 | `'。'` 是 multi-character character constant，`-Werror` 直接报错；要按 UTF-8 字节比对 |
| `'\0'` 写进 C 文件变成真 NUL | Python heredoc 里 `'\0'` 会被解释成空字节，用 `== 0` 代替 |

## 专节：封面的颜色深度

这个坑踩了两次，值得单独记。

**设备真实的颜色深度是 16（RGB565）**，来源是 `apps/arcs-mini/prj.conf`：

```
CONFIG_SDK_MODULE_LVGL8=y
CONFIG_LV_COLOR_DEPTH=16
```

**陷阱**：`apps-ui/portable/linux_sdl2/lv_conf.h` 里写的是 `LV_COLOR_DEPTH 32`——那是 **PC 模拟器**的配置，跟固件无关。第一次就是照它改成了 ARGB8888，结果数据量差一倍，封面彻底显示不出来。

正确格式：

| 项 | 值 |
|---|---|
| 颜色格式 | RGB565，2 字节/像素 |
| `lv_color_t.full` | `(red << 11) \| (green << 5) \| blue` |
| 字节序 | 小端，低字节在前（`struct.pack('<H', ...)`） |
| 尺寸 | 64×64 → 8192 字节 + 8 字节头 = 8200 |

header 的位域布局（`lv_img_header_t`，小端）：

```
bit  0- 4   cf              （LV_IMG_CF_TRUE_COLOR = 1）
bit  5- 7   always_zero
bit  8- 9   reserved
bit 10-20   width
bit 21-31   height
```

Python 侧：`struct.pack("<I", 1 | (w << 10) | (h << 21))`

## 专节：KV 丢失

**征兆**：日志反复出现 `lisa_kv_get_small_data(key: user.brightness) fail, old_len is 0`，设备重启后连不上 WiFi/云端，表情回到官方版。

**影响**：WiFi 凭证、OTA 开关（`disable_emoji_update` / `disable_app_update`）全在 KV 里，一起丢失。

**处置**：重新配网；固件启动时会自动补设 OTA 开关（`bili_ensure_ota_locks()`），所以表情和自编译固件不会再被刷回。

## 专节：烧录与分区

| 操作 | 命令 / 注意 |
|---|---|
| 只烧 app 分区 | `tools\flash-app.ps1` |
| 只烧表情分区 | `tools\flash-emoji-only.ps1`（写 `0x380000`） |
| recovery 下退出 | 必须 `adb -s BOOT-<chipid> shell reboot`；`adb reboot` 报 `error: closed` |
| `adb push` 路径 | MSYS 路径（`/f/...`）不被原生 adb 接受，要用 `F:\...` |
| emoji 分区上限 | 786,432 B，128 色 palette 才能压进去 |
| OTA 保护 | `user.disable_app_update=1` + `user.disable_emoji_update=1` |
| 换唤醒词/提示音 | 临时放开 `disable_wakeword_update` / `disable_tone_update`，完成后再锁 |
