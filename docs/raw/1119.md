¶ 进阶功能说明

Arcs-Mini 具备以下进阶功能：

支持 MCP 服务，可通过语音交互实现端侧 LED 控制、表情切换、音量与背光调节、闹钟提醒、音乐播放等；

集成 bootloader，支持通过 USB 接口使用 ADB 工具进行固件烧录更新；

支持通过 ADB shell 指令查询设备信息、配置网络、读写持久化键值（KV）等。

¶ MCP 功能

本应用提供了一部分端&云的 MCP 功能，为开发者提供自定义 MCP 能力的参考。以下为当前固件默认参与编译的 MCP 工具（源码见各 mcp_tool_*.c 文件，均通过 MCP_TOOL_DEFINE 注册）。

¶ Shell 指令

本应用支持使用数据线连接开发板 USB 接口后，通过 ADB 工具使用 shell 指令对开发板进行信息读取与配置。

ADB 工具的使用可参照《Arcs-Mini 开发板开发环境搭建》文章中关于 ADB 工具安装的说明。

¶ 连接设备并启动shell

使用数据线连接开发板 USB 接口，执行adb shell指令即可进入 shell 指令模式，输入help 指令可查看开发板支持的 shell 指令：

下文所有 kv、wifi、device 等指令均可通过 adb shell <指令> 直接单次执行，例如：

adb shell kv show

¶ version —— 查询固件版本号

打印当前固件版本号与 commit 号（源码：src/shell/cmd/version.c）：

version

输出示例：2.6.0-17322e5a

¶ device —— 设备标识管理

用于查看/配置设备接入云端的产品 ID（pid）、密钥（sid），以及读取设备 ID（源码：src/shell/cmd/id_cmd.c）。

获取设备配置相关的指令提示：

device

读取设备 ID（输出芯片 ID 与 KV 中保存的设备 ID）：

device get_device_id

读取当前接入的大模型产品ID(pid)（未单独配置时输出固件内置默认值）：

device get_pid

配置接入的大模型产品ID(pid)，要求 36 位字符（UUID 格式）：

device set_pid <product_id>

配置接入的大模型产品密钥(sid)，要求 36 位字符：

device set_sid <secret_id>

同时支持 device get_sid 查询密钥、device reset 清除已配置的 pid/sid 并恢复默认值。

¶ wifi —— 网络配置

用于连接/断开 WiFi、扫描与管理已保存网络（源码：src/shell/cmd/wifi.c，需开启 CONFIG_WIFI_MANAGER）。

配网命令（开放网络可省略密码参数）：

wifi connect "ssid" ["password"]

断网命令：

wifi disconnect

扫描周围可用网络（列出 SSID、BSSID、信道、信号强度）：

wifi scan

列出已保存的网络：

wifi list

自动重连已保存网络，参数为重连间隔（毫秒），0 表示停止自动重连：

wifi auto 5000

若设备当前处于 4G（Modem）网络模式，wifi connect 只会保存该热点配置而不立即切换连接。

¶ sd —— TF 卡调试

扫描 TF 卡并递归列出文件（最大深度 8 层，源码：src/shell/cmd/sd.c）：

sd scan

若扫描时发现 TF 卡未就绪（例如热插拔后驱动状态异常），会自动尝试恢复：重置 SDMMC 驱动 → 重新硬件探测 → 重新挂载文件系统，然后再执行扫描。

¶ kv —— 键值配置

固件使用 KV（键值对）在 flash 中持久化保存用户配置，重启后仍然生效（源码：src/shell/cmd/kv.c）。通用操作格式：

kv set <type> <key> <value>    # 写入，type 为 int/bool/string
kv get <type> <key>            # 读取，type 为 int/bool/string/blob
kv del <key>                   # 删除某个 key（恢复默认值）
kv show                        # 列出当前所有 KV 项

¶ 音量与最小音量

查看/设置当前音量（立即生效并持久化，实际会被钳位到最小音量~100 区间）：

adb shell kv get int user.volume
adb shell kv set int user.volume 50

设置最小音量（只允许 0~10）：

adb shell kv set int user.min_volume 0

最小音量生效规则：

若当前音量大于等于新的最小音量，当前音量保持不变（如当前音量 50，设置 min=8 后仍为 50）

若当前音量小于新的最小音量，当前音量会被抬升到新的最小音量（如当前音量 5，设置 min=8 后变为 8）

恢复默认最小音量 10：

adb shell kv del user.min_volume

删除后再执行 kv get int user.min_volume 会提示失败，这是正常现象，表示当前没有单独保存该值，系统按默认值 10 生效。

¶ 交互模式

当前支持 3 种交互模式（枚举定义见 src/category/comm/app_datas.h）：

模式值
模式
说明

 | 0
 | 全双工 APP_INTERACTION_MODE_FULL_DUPLEX
 | 连续对话（无需每轮重新唤醒），播报期间支持打断（可插话）

 | 1
 | 半双工 APP_INTERACTION_MODE_MULTI_NO_INTERRUPT
 | 连续对话，播报期间不支持打断（不可插话）

 | 2
 | 单工 APP_INTERACTION_MODE_SINGLE
 | 每轮都需要重新唤醒，一轮对话结束后返回待唤醒状态

切换交互模式（设置后立即生效，会自动退出当前对话会话）：

adb shell kv set int user.int_mode 0    # 全双工
adb shell kv set int user.int_mode 1    # 半双工
adb shell kv set int user.int_mode 2    # 单工

也可以通过语音调用 MCP 工具 ls.built_in.switch_full_duplex_v2（实现于 apps/arcs-mini/mcp-tools/mcp_tool_duplex.c，最终调用 model_voice_interaction_mode_set()，定义于 apps-ui/apps/llm/models/model_voice.c）切换，例如“退出全双工交互模式”。

¶ 连续对话空闲退出超时

全双工/半双工连续对话模式下，一段时间无交互后自动退出对话，超时时间通过 KV 配置（单位毫秒，默认 20000）：

adb shell kv get int user.idle_exit_timeout_ms
adb shell kv set int user.idle_exit_timeout_ms 30000

该值在每轮对话会话启动时从 KV 重新加载，因此设置后下一轮对话即生效，无需重启设备。恢复默认值（20s）：

adb shell kv del user.idle_exit_timeout_ms

¶ 网络模式

指定设备开机使用的网络模式（0=WiFi，1=4G Modem）。开机时读取，修改后需重启生效：

adb shell kv set int user.network_mode 1

¶ OTA 升级开关

以下 4 个 key 为 int 类型，非 0（如 1）表示关闭对应分区的 OTA 升级，固件在开机检查升级时读取，修改后需重启生效。适合调试时固定固件/资源版本、防止被云端 OTA 覆盖：

adb shell kv set int user.disable_app_update 1        # 禁止 CP 应用固件 OTA
adb shell kv set int user.disable_wakeword_update 1   # 禁止唤醒词资源 OTA
adb shell kv set int user.disable_tone_update 1       # 禁止提示音资源 OTA
adb shell kv set int user.disable_emoji_update 1      # 禁止表情资源 OTA

恢复（重新允许升级）：

adb shell kv del user.disable_app_update
