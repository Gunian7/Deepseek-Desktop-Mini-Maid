¶ ARCS-MINI 工程说明

本文介绍 arcs_mini 工程的主要目录，以及 .agents/skills 中各 Skill 的用途。默认目标是 ARCS-MINI 的 arcs_mini 板型；Arcs-Mini3 使用独立的 arcs_mini3 板型，两个板型的引脚、外设和固件不能混用。

¶ 主要目录

路径
作用

 | apps/arcs-mini/
 | ARCS-MINI CP 核应用，包含产品业务、应用配置和功能模块。日常产品功能优先在这里修改。

 | apps/remote-ap/
 | AP 核固件，负责算法和 AP 侧处理。只有涉及 AP 功能时才需要单独构建。

 | apps-ui/
 | UI 相关应用和资源工程。

 | src/
 | 项目级公共代码和跨应用共享逻辑。

 | boards/
 | 本项目的板型或产品变体覆盖配置。

 | arcs-sdk/
 | ARCS SDK 子模块，提供 SoC、RTOS、HAL、驱动、组件、板型基础配置和构建支持。

 | arcs-sdk/boards/arcs_mini/
 | arcs_mini 基础板型配置和 pinmux。

 | arcs-sdk/boards/arcs_mini3/
 | arcs_mini3 基础板型配置和 pinmux。

 | modules/
 | 外部公共模块，例如 ebus、lisaui 和 lschat。

 | res/arcs-mini/
 | Mini 的 boot、AP、提示音、唤醒词、表情和资源包等烧录资源。

 | res/arcs-mini3/
 | Mini3 专用 boot、AP 和分区表；共享资源按分区表引用对应目录。

 | build*.sh、build*.ps1
 | Linux/WSL/macOS 和 Windows 的构建入口。

 | adb_download.sh、adb_download.ps1
 | 通过 ADB 按分区表烧录固件和资源。

 | tools/
 | 构建、烧录和调试工具，例如 cskburn 与内置 ADB。

 | tests/、doc/、docs/、cloud/
 | 测试、工程文档、产品文档和云端相关文件。

构建后的实际配置以 build/.config 为准，应用默认配置位于 apps/arcs-mini/prj.conf。修改 SDK 子模块后，需要同时确认主仓库中的 submodule 指针是否正确。

¶ 构建

在仓库根目录执行：

Arcs-Mini2
Arcs-Mini3
¶ Windows
.\build.ps1 -S .\apps\arcs-mini -DBOARD=arcs_mini

¶ Linux
./build.sh -S ./apps/arcs-mini -DBOARD=arcs_mini

¶ Windows
.\build.ps1 -S .\apps\arcs-mini -B build-arcs-mini3 -DBOARD=arcs_mini3

¶ Linux
./build.sh -S ./apps/arcs-mini -B build-arcs-mini3 -DBOARD=arcs_mini3

¶ 烧录

Arcs-Mini2
Arcs-Mini3
¶ Windows
.\adb_download.ps1 -S res\arcs-mini app

¶ Linux
./adb_download.sh -S res/arcs-mini -B build app

烧录前脚本会检查 ADB 的 product、model、device 是否与资源目录对应的板型一致。版型不匹配时会输出中文错误并停止烧录。

¶ Windows
.\adb_download.ps1 -S res\arcs-mini3 -B build-arcs-mini3 app

¶ Linux
./adb_download.sh -S res/arcs-mini3 -B build-arcs-mini3 app

烧录前脚本会检查 ADB 的 product、model、device 是否与资源目录对应的板型一致。版型不匹配时会输出中文错误并停止烧录。

¶ Skill 的作用

Skill 是 .agents/skills/<skill>/SKILL.md 中的项目工作流说明。它们不会编译进固件，而是约束 Agent 使用正确的目录、命令、验证步骤和设备操作顺序。可以直接使用 /build、/flash 等命令，也可以用自然语言描述目标；涉及多个阶段时会按顺序组合 Skill。

Skill
用途

 | coding
 | 修改应用、公共代码、ebus、AT 命令、Kconfig 和 CMake。

 | build
 | 编译 ARCS 应用和 AP/CP 固件。

 | device
 | 处理 GPIO、PWM、I2C、SPI、UART、屏幕、音频、pinmux 和设备配置。

 | flash
 | 通过 ADB 或 cskburn 烧录固件，选择分区并执行烧录后的检查。

 | run-log
 | 获取和分析 ADB shell 或串口日志。

 | review
 | 按项目分支规范审查代码和变更。

 | commit
 | 规范化 Git 提交、submodule 指针和推送顺序。

 | mcp
 | 开发或维护 ARCS-MINI 端侧 MCP 工具。

 | local-memory
 | 保存用户明确要求记住的本机开发偏好，不提交到仓库。

一个典型流程是：修改应用使用 coding，编译使用 build，烧录使用 flash，启动后查看日志使用 run-log，确认变更后使用 review 和 commit。

¶ 修改位置建议

产品业务和 CP 功能       -> apps/arcs-mini/
AP 算法或 AP 配置         -> apps/remote-ap/
项目共享业务代码          -> src/
产品变体覆盖配置          -> boards/
基础板型、驱动或 pinmux   -> arcs-sdk/boards/<board>/
通用 SDK、HAL、RTOS       -> arcs-sdk/
提示音、唤醒词和资源包    -> res/<resource-dir>/

优先修改应用层和项目层代码；只有确实需要调整基础平台能力时才修改 arcs-sdk，并在主仓库提交对应的子模块指针。
